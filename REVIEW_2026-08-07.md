## 5. 🔴 Security & Correctness Bugs (Enterprise Package)

### 5.1 `timingSafeEqual` without length check — **crash / DoS**

**File:** `packages/enterprise-saas/src/security/ApiKeyManager.ts:52-55`

```ts
validateKey(plainKey: string, storedHash: string): boolean {
  const computedHash = this.hashKey(plainKey)
  return crypto.timingSafeEqual(Buffer.from(computedHash), Buffer.from(storedHash))
}
```

`crypto.timingSafeEqual` **throws** if buffers differ in length (Node docs: “throws if buf lengths differ”). `computedHash` is hex (64 chars) but if `storedHash` is truncated/corrupted/old format, the process crashes — unauthenticated DoS. Same bug in `RequestSigner.verifySignature` line 72.

**Repro:**
```ts
new ApiKeyManager().validateKey("kilo_x_y", "short") // throws RangeError, 500 instead of 401
```

**Fix:**
```ts
if (computedHash.length !== storedHash.length) return false
try { return crypto.timingSafeEqual(...) } catch { return false }
// or use node:crypto.timingSafeEqual with hash length constant + hex-decode first
```

Also: hash comparison should be on **decoded bytes**, not hex strings, to keep constant-time over 32 bytes not 64. Consider `Buffer.from(hash, 'hex')`.

**Severity:** P0 — auth path crash.

### 5.2 `TenantContextManager` — **concurrency isolation failure**

**File:** `TenantContextManager.ts:12,22,40`

```ts
private currentContext: TenantContext | null = null
createContext(tenant) { this.currentContext = context; return context }
withContext(tenant, fn) { this.createContext(tenant); try { return await fn(context) } finally { this.clearContext() } }
getCurrentContext() { return this.currentContext }
```

- Single mutable field → **not request-scoped**. Under concurrent async requests (typical Node server), two interleaved `withContext` calls will clobber each other; `getCurrentContext` returns wrong tenant → **cross-tenant data leak**.
- `withContext` does `await fn()` but if `fn` does fire-and-forget async work after `clearContext()`, context is lost.
- No `AsyncLocalStorage` fallback.

**Fix:** Use `AsyncLocalStorage<TenantContext>` (Node 14+). Keep `currentContext` as fallback for CLI/single-thread.

```ts
import { AsyncLocalStorage } from 'node:async_hooks'
private als = new AsyncLocalStorage<TenantContext>()
withContext<T>(tenant, fn) { return this.als.run({tenantId: tenant.id, tenant, correlationId: nanoid()}, () => fn(this.als.getStore()!)) }
getCurrentContext() { return this.als.getStore() ?? this.currentContext }
```

**Severity:** P0 — violates the core “tenant isolation” guarantee.

### 5.3 `RateLimiter` — **in-memory, unbounded, non-distributed**

```ts
private requestLog: Map<string, number[]> = new Map()
```

- Claims “stateless, horizontal scaling ready” — false. Each process has isolated Map; burst across replicas bypasses limit.
- No eviction besides `cleanup()` manual call → memory leak (timestamps never expire unless `checkLimit` called for that key).
- `cleanup()` iterates entire Map O(N) — expensive if attacked with random keys (DoS via key cardinality).
- `burstSize` field defined but never used.
- `getStatus` re-filters on every call — double work.

**For prod:** Requires Redis/memcached token bucket, or at least LRU with TTL. Document as “local dev limiter, not prod”.

---

### 5.4 `InputValidator` — **naive sanitization**

```ts
sanitizeHtml(input) { return input.replace(/<[^>]*>/g, "") }
sanitizeFilePath(input) { return input.replace(/\.\./g,"").replace(/\\/g,"/").replace(/^\/+/,"") }
containsSqlInjection(input) { return [/(SELECT|INSERT|DROP)/gi, /(;|--|...)/gi].some(r=>r.test(input)) }
containsXss(input) { return [/<script/gi, /javascript:/gi, /onerror=/gi, ...].some(r=>r.test(input)) }
```

- `sanitizeHtml` does not handle attributes, entities (`&lt;`), or nested tags. Should recommend `DOMPurify`/`sanitize-html`.
- `sanitizeFilePath`: `replace(/\.\./g,"")` turns `....//` → `//` → still traversal via `.../...`. Fails on `..%2F`. Should use `path.normalize` + `path.resolve` against allowed root.
- `containsSqlInjection` false-positives on normal English (“Please SELECT an option”), misses encoded injections (`SeLeCt`, `UNION/**/SELECT`). Not suitable for blocking.
- `containsXss` misses `<svg/onload>`, `data:text/html`, `eval(`. Same.
- `sanitizeString` only strips `\0` + trims — no length check, no control chars.
- Tests assert these weak helpers work — gives false confidence.

**Recommendation:** Keep `validate` (Zod) — excellent. Deprecate or rename `contains*` to `maybeContains*` / keep as heuristic for logging only, never for allow/block. For prod, use parameterized queries (not string detection) and a real HTML sanitizer.

---

### 5.5 `AuditLogger` — **in-memory, O(n) query, no persistence**

- `events: AuditEvent[] = []` grows unbounded → OOM.
- `query()` does linear filter + **mutating sort** `filtered.sort(...)` on the shared array — will corrupt order for concurrent callers, and O(n log n) per query.
- `exportLogs` loads `MAX_SAFE_INTEGER` into memory.
- No indexing on `tenantId`, no `correlationId` deduplication, no nonce replay cache (required by `RequestSigner`).
- `detectSuspiciousActivity` uses string `includes("login_failed")` — brittle; will match `x_login_failed_y` but also `not_login_failed` etc. Should use exact `action === AuditActions.LOGIN_FAILED`.

For a “compliance” component, needs pluggable storage (append-only DB, retention).

---

### 5.6 `StructuredLogger` — **writes to `console.log`, no redaction**

- Calls `console.log(JSON.stringify(entry))` — no level filtering beyond `shouldLog`, but `console.log` always INFO level. Should use `console.debug/info/warn/error`.
- `minLevel` default `"info"` but `LogLevel` enum values are lowercase — comparison works only because `shouldLog` uses string array includes; brittle.
- No sensitive field redaction (will log `apiKey`, `password` if passed in metadata). Needs deny-list.
- `HealthMonitor.memory` uses `process.memoryUsage().heapTotal` denominator — should use `rss` or configured limit; `percentUsed` calculation wrong under V8 heap growth.

---

### 5.7 `TenantManager` — **missing validation & atomicity**

- No Zod validation on `createTenant` input (despite `CreateTenantSchema` existing) — caller can pass arbitrary `tier`/email and it trusts it.
- `upgradeTier` preserves `current*` counters but does not validate downgrade path, nor prorate billing. `status` forced to `ACTIVE` even if was `SUSPENDED`.
- `resetQuotas` only resets `currentApiCalls` + `currentTokens`, leaves `currentStorageMb`/`currentUsers` stale — should reset all or document.
- `getDefaultFeatures` uses switch fallthrough — intention unclear, comment needed; FREE gets only `codeGeneration:true`, but ENTERPRISE gets all — okay but not explicit.
- `trialEndsAt` set 14 days exactly — no business-day handling, no timezone config, okay for v0.

---

### 5.8 `QuotaEnforcer` / `UsageTracker` — **not atomic, not persistent**

- `consume*Quota` returns new `Tenant` object (immutable) — good, but caller must persist returned object. No docs warn about lost update if caller forgets `tenant = enforcer.consume(...)`.
- `check*Quota` uses `currentApiCalls` counters, `UsageTracker` stores separate `events` Map — two sources of truth that can diverge. Should derive quota from tracker or sync them.
- `UsageTracker.getUsageSummary` iterates all events per query O(n). Needs index.

### 5.9 Minor

- `packages/enterprise-saas/src/index.ts` exports everything via `export *` — pollutes namespace (e.g., `Role` vs `HealthStatus`). Better to namespace exports.
- `package.json` sets `exports["."]` to `./src/index.ts` (TS source) — correct for `workspace:*` but breaks if published without build. Add `types`/`default` for built output.
- `RateLimiter` `Rule` field `burstSize?` unused → remove or implement.
- `RequestSigner` RSA branch throws generic `Error("not yet implemented")` — should throw `NotImplementedError` with `algorithm`.
